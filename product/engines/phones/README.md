# @cluenori/phones

The phones paired with a deployment: pairing one by a link the web shows as a QR code, the key each
calls the API with, when and where each last called, the token pushes reach each by, and removing
one.

## Use it

```ts
const phones = yield* Phones

// On the web: a link to show as a QR code, good once for 10 minutes.
const pairing = yield* phones.startPairing(member, "https://cluenori.example")
// { link: "cluenori://pair?url=https%3A%2F%2Fcluenori.example&code=…", expiresAt }

// The phone opens it and pairs with the code: its key is returned only now.
const { phone, key } = yield* phones.pair({ code, model, systemVersion, appVersion }, caller)
// A used or expired code fails with PairingCodeRejected.

// Each call it makes: who it acts for, recorded as last seen.
const actor = yield* phones.authenticate(key, caller)
// After `phones.remove(member, phone.id)`, PhoneKeyRejected.
```

## Owns

- **Data:** phones with their keys' digests and who they act for (`phones_phones`), when and where
  each last called (`phones_seen`), open pairings by their code's digest (`phones_pairings`), and
  the push token each last registered, with its APNs environment (`phones_push`).
- **Rules:**
  - A pairing code is good once, for 10 minutes; at most 5 are good at once.
  - A phone's key is `cluenori.phone.<phone ID>.<secret>`, shown once; only its SHA-256 digest is
    kept. A phone acts for whoever started its pairing.
  - The app's User-Agent, `Cluenori/<app version> iOS/<iOS version>`, keeps a phone's versions
    current: a call that says new ones updates them, with `phone.updated`.
  - What people call each model (`iPhone19,3` is an iPhone 18 Pro Max), from Xcode's list of
    simulated devices; a model it doesn't know shows its identifier.

## Does not own

- **Telling a phone anything:** the notifications engine sends alerts to `pushTargets`, and
  forgets a token APNs says is gone.
- **The API token:** the Worker's `ApiToken`.
- **The caller's address and country:** the host reads them from Cloudflare's headers.

## Contract

`src/index.ts`. The host serves pairing and the phone list, and asks `authenticate` about every
bearer token that looks like a phone's key; `PhonesGroup` and `PairingGroup` are the API's part.

## Depends on

Foundation's `ActivityLog`, and `Crypto` for codes, keys, IDs and digests.

## Activity

`phone.paired` by whoever started the pairing; `phone.updated` by the phone's actor when its versions
change; `phone.removed` by whoever removes it.

## Decisions and constraints

- **A phone registers its push token with its own key,** which `registerPush` checks: no other
  credential can point a phone's alerts elsewhere. A token is on one phone only, the one that
  registered it last, so a reinstalled app never gets an alert twice. Registering is without
  activity, since iOS changes a token on its own.

- **Pairing by link.** The QR code holds `cluenori://pair?url=<deployment>&code=<code>`, so the
  Camera opens the app, and a link pasted into a simulator works too. The deployment is the origin
  the web reached, as phones reach it.
- **When a phone calls isn't a record.** Last seen is kept apart, without activity, and written at
  most once a minute from one address, so a phone's calls rarely write.
- **No device names.** iOS gives an app the name its owner chose only with an entitlement Apple
  grants on request; the model's name is what tells phones apart.
- **Each phone call asks the workspace's object,** one request, before the call's own.
- `src/apple-models.ts` is generated by `bun run generate:apple-models` on a Mac with Xcode; run it
  when a new Xcode knows new devices.
